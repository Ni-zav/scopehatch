# Paired comparison — existing spreadsheet/document process

## Controlled question

Does Scopehatch reduce errors or manual effort **without** shifting risk into unsupported quantities, unreviewed commercial commitments or extra setup/support? A faster unreviewed AI draft is not equivalent to a correctly approved unsigned proposal.

### Preparation

1. Ask the operator which spreadsheet/doc process they actually use; don't redesign their existing template just to favor the pilot. Use fictional scenarios and approved fictional catalog values in **both** arms; real customer documents are unnecessary.
2. Keep the scope request, currency, per-service rates, requirement clarifications, output expectations and reviewer constraint identical. For the comparison arm, give the participant the fictional text as a copy/paste input to the ordinary document/spreadsheet. For Scopehatch, paste it unchanged into a project.
3. Counterbalance where practical: group 1 uses existing workflow first and group 2 uses Scopehatch first, with **matched different scenarios** to minimize memorization; record order, matching and experience. An exact repeated scenario is useful for fidelity but introduces learning bias.
4. Start timing at receiving the fictional brief, stop separately at **first reviewed draft** and at **completed independently reviewed draft**. Include clarification/rework and support time; don't compare a blocked quote with a forced finished one.
5. Have a person other than the author audit correctness using [observation rubric](04-observation-sheet.md). Rate failures of both processes consistently, including manual spreadsheet errors. Note whether the baseline process genuinely offers immutable audit/history; mark not available rather than assuming it.
6. After the paired exercise, ask about practical preference and missing features; record statements as opinions, not proven repeat use or payment intent.

### Analysis rules

- Report raw paired records first, then median time/corrections **only if measured**; show cohort sizes and how many cases were excluded or blocked. Do not claim significance or ROI from a small convenience sample.
- Split end-to-end elapsed time from **active operator/reviewer time**, setup/maintenance time and help time. Never call stalled tasks instantaneous.
- A correctly blocked estimate is a **positive safety outcome**; compare whether the spreadsheet/doc process flags the same missing facts rather than treating an invented priced PDF as success.
- Treat wrong tenant visibility, self-approval, stale approval or price provenance failure as a **release blocker**, regardless of subjective satisfaction.
- If the participant prefers current spreadsheet/AI draft tooling, record that and assess export/interoperability needs before adding features. Do not suggest CRM as the automatic answer.
