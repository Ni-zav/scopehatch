# Model evaluation adapter

`openai-compatible.mjs` implements an explicitly configured OpenAI-compatible chat-completions adapter for local Ollama or an approved HTTPS endpoint. It exports `extractBrief(input, context)` for compatibility with the original evaluation CLI and `createEvaluationAdapter({config,fetchImpl})` for the Sprint 02 benchmark and deterministic network-free tests.

The new benchmark command is described in [tests/evaluations/README.md](../../tests/evaluations/README.md). For live execution it requires `EVAL_LIVE=I_AUTHORIZE_MODEL_CALLS`, `EVAL_PROVIDER=ollama|openai-compatible`, `EVAL_MODEL_URL`, `EVAL_ALLOWED_HOSTS`, and `EVAL_MODEL`. Optionally set `EVAL_API_KEY` via a secret manager. No remote HTTP, endpoint-embedded credentials, query secrets, redirects or unallowlisted hosts are accepted. Loopback HTTP is permitted for Ollama. This module does not auto-opt-in to model calls.

The adapter uses the existing versioned extraction prompt from `packages/extraction/prompt.mjs`, restricts response size, flags HTTP/network failure with safe codes, and never logs raw completions, request bodies or provider errors. Its `observations()` output includes numeric metering only when provider reports both token counts; nonstandard provider-reported cost requires both `usage.cost` and `usage.currency`. Missing metering stays unknown. Never assume a successful provider HTTP response means a grounded suggestion or an authorized approval.

For live API workflow verification, the original `runner.mjs` still accepts an operator-supplied `--workflow-adapter` implementing `runWorkflowCase({caseId,scenario,expected})`. Such an adapter must verify signed identity, tenant isolation, independent review, current revision/catalog, authoritative pricing and durable audit via real authenticated endpoints. No such API adapter is included here because production credentials and tenancy configuration cannot be safely guessed.
